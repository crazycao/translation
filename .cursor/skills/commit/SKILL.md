# Commit

收集当前仓库未提交的改动，用中文整理成提交说明，然后提交。

## 用户已提供说明

调用时 `/commit` 后面带有说明（例如 `/commit 添加能力文档`）时，把这段文字原样作为提交说明。

- 不要执行 `git diff` 或 `git log`，不要阅读改动，不要改写、缩短或补标点。
- 不要向用户确认。
- 仍需执行下面的「提交」步骤，把文件提交进去。

## 用户未提供说明

1. 在仓库根目录并行执行：
   - `git status`
   - `git diff`（含已暂存与未暂存）
   - `git log -8 --oneline`（仅用于了解仓库近期在提交什么）
2. 没有可提交的改动时，直接说明并停止，不要创建空提交。
3. 阅读 diff，拟定一条提交说明：不超过 10 个字，概括这次改了什么，不要附加英文标题、标点或变更清单。优先用「添加……」「更新……」「修正……」开头；只有这三种都说不清时，才换别的写法。
4. 执行 `git commit` 之前，先把拟定说明和将要提交的文件发给用户确认。用户可以：
   - 确认就用这条说明提交；
   - 直接给出一条新说明。
5. 用户确认或给出新说明之前，不要执行 `git commit`。若用户给出新说明，原样使用，不要改写。

## 提交

1. 没有可提交的改动时，直接说明并停止，不要创建空提交。用户已提供说明时，用 `git status` 判断，不要为此阅读 diff。
2. 不要提交密钥或凭据（如 `.env`、`credentials.json`、私钥）。发现这类文件时先警告，并将其排除在本次提交之外。
3. `git commit -am` 不会纳入未跟踪文件。若这些新文件属于本次改动，先 `git add` 它们，再执行提交。已跟踪文件的修改和删除交给 `-a` 处理。
4. 用下面的形式提交，把说明原样放进 heredoc，避免引号或换行把命令截断：

```bash
git commit -am "$(cat <<'EOF'
提交说明

EOF
)"
```

5. 提交后再运行 `git status`，确认结果。不要 push，不要 amend，不要改 git config，不要加 `--no-verify`。
